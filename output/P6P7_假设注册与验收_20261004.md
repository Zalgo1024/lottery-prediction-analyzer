## P6：机制缝隙类假设的注册面

**做了什么**：把 `ev/mechanism` 四轨测量的假设面注册进 discovery 假设登记册体系，让「测过什么」可追溯。

### 1. `discovery/hypothesis_registry.py` — 新增 `_gap_templates(lottery)`

| 彩种 | 注册的轨 | 说明 |
|---|---|---|
| 双色球 / 大乐透 | **A**（注数比 R）+ **B**（开出号分位 ū） | 两条判定轨 |
| 排列5 | **A′** + **C** | 数字型注数比可判定 |
| 七星彩 | **A′** + **C** + **D** | 只切现行段 |
| 排列3 / 福彩3D | **只有 C** | ★ 不给 A′ |

两个设计决定：

- **按可判定性给模板，不给齐**。排列3/福彩3D 的销售额覆盖全部玩法，A′ 轨量到的是投注结构占比而非开奖倾向 —— 注册一个测不了的检验比不注册更糟：它会一直挂 proposed，让读者以为「还没测」而不是「测不了」。
- **`adjudicating` 标记进数据结构**。C/D 轨**恒为 False**（诊断轨不参与裁决的硬纪律，写死在 `_GAP_ADJUDICATING`）—— 注册 C/D 是为了让「测过什么」可追溯，不是把它们抬进判定。

模板并入 `auto_templates` → `add_auto_hypotheses`（幂等，按 name 去重）可生成；`probe` 落盘 `track` + `adjudicating` 两字段。

### 2. `discovery/always_valid.py` — `_hypothesis_coverage` 加 `mechanism_gap` 分支

明说：**e-value 序贯监控不覆盖缝隙类假设**。理由写进文案：e-value 监控的对象是「号码分区频率」，缝隙类检验的是「中奖密度 / 开出号冷门度」，两个统计量；检验入口指向 `python cli.py gap <彩种>`。输出加 `track` / `adjudicating` 两字段。
