## 1. 硬红线怎么保证的

`mechanism_gamma`（`ev/gap.py`）是红线的唯一实现点：模型未 Go / γ 不可折算 /
γ 的 CI 含 0 ⇒ **返回 0.0**。P4 在此基础上再加两道：

| 机制 | 做法 | 为什么 |
|---|---|---|
| **不乘 1.0，直接跳过** | `select_in_gap` 在 γ=0 时返回**传入的 base 对象本身**（`key is base` 可证） | 全组合 110 万个只有 21 万个不同分数、最大并列组 149 个。`argsort` 在完全并列时靠稳定性，差 1 ULP 就会换顺序 —— 乘 1.0 是把红线押在 BLAS 舍入方向上 |
| **模型未 Go ⇒ None** | 拿不到 z 标尺就返回 `None`，调用方跳过乘法 | 「不许静默降级」纪律：绝不用别的口径顶替 |

## 2. ★ 执行中撞破了一次红线（已修）

端到端跑真实数据时发现：快照明写 `双色球 γ=-0.0185 **显著=False**`，
但状态却报 `倾斜=**True**`，推送 footer 直接输出「机制倾斜**已激活**：γ=-0.0185（偏向热门）」。

**根因**：P5 为了「不触发测量」从快照取 γ，而快照里的 γ 是**原始测量值**；
`tilt_state` 只判 `γ != 0` ⇒ 完全绕过了 `mechanism_gamma` 的红线
（红线是 `if not 显著: return 0.0`）。

**修法**：

1. `tilt_state` 加 `significant` 参数 —— 给 `False` ⇒ **强制按 γ=0 处理**；
2. 措辞分家：`γ` 非零但不显著 ⇒「γ 未过显著门（CI 含 0）」；`γ` 本身不可得 ⇒「γ 不可折算」；
3. 快照加 `γ_可倾斜`（= γ if 显著 else 0.0）作兜底字段；
4. **消费方一律传原始 γ + 显著位**，由 `tilt_state` 统一过红线（集中判断，不分散）。

修后六彩种全部 `倾斜=False`：

```
双色球   倾斜=False  原因=γ 未过显著门（CI 含 0）→ 按 γ=0 处理，不做倾斜
大乐透   倾斜=False  原因=γ 不可折算（模型未 Go / 无 z 标尺）→ 按 γ=0 处理
排列5    倾斜=False  原因=γ 不可折算
七星彩   倾斜=False  原因=γ 不可折算
排列3    倾斜=False  原因=γ 不可折算
福彩3D   倾斜=False  原因=γ 不可折算
```

新增 3 例锁死：`test_tilt_state_respects_significance_flag`、
`test_tilt_state_activates_when_significant`、`test_snapshot_exposes_redline_filtered_gamma`。

## 3. P4 做了什么

### 新模块 `ev/mechanism/gap_select.py`

| 函数 | 作用 |
|---|---|
| `mechanism_multiplier` | 乘数 `exp(-γ·ss)`，归一到均值 1。γ>0（开奖偏冷门）⇒ 冷门乘数大；γ<0 自动反向 |
| `select_in_gap` | 基础分 × 乘数。γ=0 ⇒ `key is base`。返回含**不含 key** 的 `状态` 子字典 |
| `tilt_state` | 纯标量状态（pending / 看板 / 推送共用） |
| `crowd_gate` | 数字型 sampler 的反大众阈值。γ=0 ⇒ 0.5（逐位不变）；γ>0 下移（上限 0.40、下限 0.10）；**γ<0 不许上抬** |

⚠️ `ss` 必须用 `popularity._score_std`（**逐特征累加**），不能用 `Fz @ beta`：
BLAS gemv 在不同行数下累加顺序不同 → 差 1 ULP → 并列组边界跳变。

### 接线

- `ev/selection.py`：向量化路径在 `eff1` 算完、`argsort` 之前乘乘数；
  **「一等奖实得」的 fallback 改回未倾斜的 eff1**（否则展示字段被乘数污染）；
  返回加 `机制倾斜`（**只带标量 `状态`** —— 塞 `key` 会把 3000 个 float 写进 pending，实测踩到）。
- `ev/sampler.py`：**仅七星彩**生效，把硬编码的 `crowding_quantile(cand) > 0.5` 换成 `> gate`；
  返回加 `反大众阈值` / `机制倾斜`。顺手改掉 docstring 里的「裁判层已否决预测」钢印。

## 4. P5 做了什么

### 新模块 `ev/mechanism/snapshot.py`

`mechanism_snapshot()` —— **只读缓存，绝不触发新测量**（一次完整测量约 17s，
出号路径付不起，看板刷新更不该）。缓存缺失 ⇒ `None` ⇒ 调用方显式写「无测量缓存」，
**不**用空表粉饰成"无缝隙"。返回带 `测量时间` / `指纹` / `来源` 供判新鲜度。

放在测量层而非 feedback：pending / 看板 / 推送三处都要同一份轻量数据。

### pending 三字段

`缝隙快照` / `机制γ` / `机制倾斜`，**挂在顶层、不进「预测号码」**
⇒ 保住「号码组数 == len(预测号码)」契约（实测 3 == 3 ✓）。

补写放在**单一咽喉** `record_pending_prediction`，不让 5 个生产调用点各自透传
—— 历史上 `record_pending` 漏过 2 次（rule 分支、`_predict_generic` 分支）。

`evaluate_pending_predictions` 带过字段，**放在 `_fb_key` 之后**
（新增字段不得改变去重键，否则同批会重复入账）。

### 看板与推送

- 新增 `/api/audit/gap/<lottery>`（带 `?refresh=1` 才重算）与 `/api/audit/gap_global`；
  **未测量时返回 `未测量=True` + 诚实说明「≠ 无缝隙也 ≠ 已证明公平」**。
- `audit.html` 第 ⑧ 卡 + `loadGap()`：裁决 `none` 显示「未检出」（**绝不**写"已证明公平"），
  缓存缺失显示「尚未测量」+ 运行命令；附六彩种汇总表。
- 推送 footer 改**条件式**：

  > 仅供研究记录；在「开奖对全部组合等可能」的前提下单注中奖概率恒定、整体期望为负，
  > 请勿用于投注决策。该前提由四轨测量独立检验（见 `python cli.py gap`）；
  > **未检出偏离 ≠ 证明开奖公平**。

  另加一行**只在真激活时才出现**：γ=0 时不加（高频推送天天挂「未激活」是噪音），
  激活是异常事件，必须显式告知。
