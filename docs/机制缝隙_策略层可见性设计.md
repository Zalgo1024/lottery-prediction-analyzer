> 2026-10-13 · 供决策用，**尚未动任何代码**
> 需求原话：「在这些策略层，也能够有实际的策略显示出来，不然我通过项目内我都看不到具体这个机制跑的怎么样」

## 一、问题诊断：为什么战绩榜看不到它

战绩榜（`/records`）与命中历史（`/hits`）的数据链是：

```
出号 → data/feedback.py::record_pending_prediction（每注带「策略」名）
     → 开奖后 evaluate 写入 training/feedback/<彩种>_feedback_history.json
     → data/records.py::get_feedback_records 按「策略」字段分组聚合
```

而机制缝隙（γ 倾斜）在这条链里**从来不是一个策略名**，它只是乘在底层策略打分上的修饰层：

- `ev/selection.py:151` —— `GS.select_in_gap(lottery, R, eff1, gamma)`，乘在「一等奖实得」上
- `ev/sampler.py:122` —— `crowd_gate(gamma)`，改反大众分位阈值（**仅七星彩生效**）

出号时策略名仍是底层那个（高频/遗漏值/区间均衡/ML），倾斜只作为附加字段 `机制倾斜` 挂在 pending 顶层。聚合时它被底层策略吞掉了。

**叠加三个原因，导致「看不到」：**

| # | 原因 | 性质 |
|---|---|---|
| 1 | 它是乘数，不是策略名 ⇒ 聚合时被底层策略吞掉 | 实现形态 |
| 2 | 当前 6 彩种 γ **全部为 0**（见下）⇒ 逐位退化成底层策略 | 数据现实 |
| 3 | 接线范围窄：只接乐透型红蓝选号 + 七星彩 sampler；排列3/排列5/福彩3D 未接 | 覆盖范围 |

### 关键事实：γ 现在全是 0

刚读的快照（2026-10-13）：

| 彩种 | 裁决 | 判定轨 | R | ū | γ | 显著 | γ_可倾斜 |
|---|---|---|---|---|---|---|---|
| 双色球 | none | A+B | 0.993989 | 0.5012 | −0.0156 | 否 | **0.0** |
| 大乐透 | none | A+B | 0.977885 | 0.49641 | 不可折算 | — | 0.0 |
| 排列5 | none | A′ | 1.03022 | — | 不可折算 | — | 0.0 |
| 七星彩 | none | A′ | 0.991864 | — | 不可折算 | — | 0.0 |
| 排列3 | no-track | 无 | — | — | — | — | — |
| 福彩3D | no-track | 无 | — | — | — | — | — |

双色球 γ=−0.0156 非零但 CI 含 0 ⇒ 走红线归零（这正是 2026-10-04 修的那个漏洞的正确表现）。

**所以「它跑得怎么样」在当前数据下没有诚实答案** —— 一个恒等于底层策略的乘数，不可能有独立战绩。这不是实现疏误，是红线设计的必然结果。

### 展示文案（诚实边界，须过黑名单扫描）

- γ=0 或不可折算：「**未激活**：γ=0（不可折算或 CI 含 0）⇒ 出号与基础策略**逐位相同**，故无独立战绩样本。这不是「开奖公平」的证明，只是「当前测量未支持非零倾斜」。」

3. 文案过 `tests/test_narrative_unbinding.py` 黑名单（不可出现「更可能/更准/提高命中/预测号码/优势」）；
4. `records.py` 聚合不受影响（该卡片不进 `strategies` 字典）。

### 红线风险

低。纯只读展示。唯一要注意：**不得把「未激活」写成「无缝隙」或「已证明公平」**。

## 四、形态 2：影子对照台账（第一版设计，已被实测证否）

> ⚠️ **本节保留为历史记录**：第一版设计用「同池同 seed、只换 γ」做对照，2026-10-13
> 实测证明 γ 对选号恒等于空操作（第八节）⇒ 该对照无意义。**最终设计见第七节**：
> 复用 `ev/trials.py` 已在跑的「排序 vs 随机」阴性对照，接进战绩榜。

**目标**：让机制倾斜产生与主出号**不同**的号码，并行记账、开奖后一起评估，从而几十期后能真回答「倾斜有没有用」。

### 核心设计

利用**已存在的两个支点**（这是成本低的关键）：

1. `ev/selection.py:110` `_select_redblue_vectorized(..., mechanism_tilt=True, gamma=<值>)` —— **已支持显式 γ**；
2. `ev/sampler.py:100` `sample_tickets(..., mechanism_tilt=True, gamma=<值>)` —— 同样支持。

即：影子批次 = 用同一候选池、同一出号参数、**只把 γ 换成固定试验值**，再跑一次选号。

范式参照项目已有的两处：
- `ev/selection.py:191 control_tickets` —— 同池阴性对照（唯一差异是「有没有排序」）；
- `train/anchor_trainer.py` —— 走前验证、JSONL **全量落账、不挑好的不丢差的**、配对 z 检验。

### 试验 γ 怎么定（**必须你拍板**）

实测 γ 现在全是 0 ⇒ **影子取实测 γ 就毫无意义**（会逐位等于主出号）。所以试验 γ 是一个**假设性对照值**，与 `min_effect=0.03` 门槛同量级。候选：

| 取值 | 含义 | 代价 |
|---|---|---|
| 0.03 | 与效应量门控同量级，最保守 | 位移可能太小，长期才看得出 |
| 0.05 | 门控的 ~1.7 倍 | 中等 |
| 0.10 | 明显位移 | 偏差大，但更易出结论 |

⚠️ 无论取哪个，都必须在页面与台账里**固定标注**：「试验 γ 为假设性对照值，**非测量结论**；实测 γ 见「机制缝隙」状态卡。」

### 改动清单

| 文件 | 改动 |
|---|---|
| `config/mechanism_trial.json` | **新文件**：`{"启用": false, "试验γ": 0.05, "策略名": "机制缝隙(影子)", "适用范围": ["双色球","大乐透","七星彩"]}` |
| `config.py` | 读取上述配置；默认 `启用=false`（**默认关**） |
| `web/utils.py` | 出号主链路末尾追加影子入账调用（不影响主出号返回） |
| `data/feedback.py` | ① `record_pending_prediction` 接受影子标记；② **权重分配排除影子策略**；③ **动态出号数量安全阀排除影子策略** |
| `data/records.py` | `STRATEGY_ORDER` 追加 `"机制缝隙(影子)"`（或靠 `ordered_names` 自动追加，需确认排序位置） |
| `web/templates/records.html` | 战绩表新增该行 + 固定说明横幅 |
| `web/templates/hits.html` | 命中详情显示影子标记 |
| `ev/selection.py` / `ev/sampler.py` | **预计不用改**（已有 gamma 参数） |

### 新增字段（pending / feedback 记录）

```json
"机制试验": {
  "类型": "影子",
  "γ": 0.05,
  "对照组": "高频策略",
  "说明": "假设性对照值，非测量结论；实测 γ 见机制缝隙状态卡"
}
```

影子注的 `策略` 字段 = `"机制缝隙(影子)"`。

### 为什么这样设计能安全共存

`data/feedback.py:1131` 的去重键是：

```
_fb_key = (档位, "RB"/"NUM", 期号, 策略, 预测号码)
```

策略名不同 ⇒ 影子注与主出号**天然不冲突**，同期可共存。`records.py:79` 的 `ordered_names = [STRATEGY_ORDER 里有的] + [其余按出现顺序]` ⇒ 新策略名会自动出现在榜单末尾。

### 测试点（重点，风险集中在这里）

1. **γ=0 或配置关闭时，影子批次一条都不出**（不能空转）；
2. **影子策略不进 `_update_strategy_weights`** —— 否则污染反馈权重，间接影响生产出号；
3. **影子策略不进动态出号数量的命中率安全阀** —— 否则污染滑轨（这是 10-11 刚定的「滑轨=最终注数」口径）；
4. 影子批次遵守马后炮防护（`feedback.py:391`，目标期已开奖则拒）；
5. `compress_tickets` 对影子批次的行为要明确（建议影子批次**不压缩**，保持与主出号同注数才好比较）；
6. 影子策略名不含「ML」/「统计训练」字样（否则被 `normalize_strategy_name` 归并）；
7. 文案过黑名单扫描；
8. 端到端：造一次影子出号 → 评估 → 战绩榜出现该行 → 权重文件不含该策略。

### 红线风险：**中**

最大风险是**影子批次被误读成「生产策略在跑」**。缓解措施（全部必做）：

- 配置**默认关闭**；
- 策略名带「影子」二字；
- 页面**固定显示**说明横幅，不随数据变化；
- 台账与页面都标注「试验 γ 为假设性对照值，非测量结论」。

### 统计功效提醒

即便跑起来，也要**几十期**才有意义。项目里已有前车之鉴：D 轨派奖期只有 21 期 ⇒ 只能写「未检出差异且功效极低」。影子台账早期大概率也是这个状态，文案要先说清，否则又会变成「看着像结论其实是噪声」。

## 五、形态 3：正式策略化 —— 不建议

把 γ 倾斜改名成独立策略、替换底层策略名。问题：

- γ=0 时它与底层策略**逐位相同** ⇒ 榜单出现两行一模一样的战绩，读者会以为是两个独立策略在跑；
- 一旦将来 γ 显著，它会**静默替换**用户选择的底层策略，违背「策略由用户/引擎决定」的现状；
- 收益与形态 2 相同（都能看到差异化战绩），但风险高得多。

## 七、形态 2 的最终设计（替代原「影子批次」）

### 最终做法：复用 ev/trials 的「排序 vs 随机」阴性对照

| 臂 | 定义 | 实现 |
|---|---|---|
| **A · 冷门偏好** | 同一候选池，按「一等奖实得」降序取 n | `ev.selection.select_tickets` |
| **B · 同池随机** | 同一候选池、同一低重叠约束，随机取 n（**不打分**） | `ev.selection.control_tickets` |

**唯一差异 = 有没有按冷门偏好排序** —— 这正是「机制缝隙」假设的可利用面
（买得少的组合更值钱）的直接检验。这套实验 `ev/trials.py` 早已在跑
（`TRIALS_ENABLED=True`，每组 100 注，落 `training/trials/<彩种>.jsonl`，开奖后结算），
本形态只把它的结果**接进策略战绩榜**，不重复造轮子、也不污染 `feedback_history`。

### 展示（`web/routes/records.py::api_records_trials` + `main.js::_mechanismTrialsCardHtml`）

- 只读：不生成、不入账、不触发测量；
- 两个实验臂各一行：累计中奖注数 / 中奖率 / 累计实得；
- 裁决（主终点「中奖率等价性」）+ 功效规划 + 次终点声明；
- **固定横幅**：实验批次、非生产策略；主终点理论差异为 0（用于检出 bug）；
  次终点（实得差异）在人类时间尺度不可完成，只作长期存档；
- 参与彩种 = `ev.trials.TRIAL_LOTTERIES`（双色球 / 大乐透）；固定赔率彩种显式显示「不参与」。

### 两个终点的性质（照抄 `ev/trials.py` 的诚实声明，绝不混为一谈）

- **主终点（可完成）**：中奖率等价性。理论预期 A/B **完全相等**（选号不改变中奖概率）
  ⇒ 差异显著即意味着实现有 bug；
- **次终点（不可完成）**：实得奖金差异。需真实中一/二等奖事件；双色球每组 100 注时
  中头奖期望等待约 **1136 年**，只能作长期存档与异常告警。

## 八、2026-10-13 实测：γ 是恒等于空操作的杠杆（形态 2 改设计的根因）

### 事实

第一版设计「同候选池、同 seed，唯一差异 = γ」在实测中被证否：

| 彩种 | 现象 | 根因 |
|---|---|---|
| 双色球 | n=20/50/176、γ=0.05~20 **一律逐注相同** | 排序键 `一等奖实得` 与机制打分 `ss` **严格单调**（20000 候选上 Spearman ρ = **−1.000000**、Kendall τ = −1.0）。乘 `exp(-γ·ss)`（同单调）乘以单调函数 ⇒ **乘积仍单调 ⇒ 排序不变**。数学上对任意 γ 成立。 |
| 七星彩 | 同上 | crowd 模型 `go=False`（有效样本不足）⇒ `mechanism_multiplier` 返回 None；且 sampler 在无模型时走 `_popularity_heuristic` 分支，**根本不读 `gate`** ⇒ γ 零影响。 |

### 结论（值得单独记录的发现）

**在当前模型下，「机制倾斜」不是一个可与「EV 选号」区分的独立策略** ——
它改得动排序键，改不动选出的号。原因不是接线错误，而是**共线性**：
`一等奖实得` 本身就是「越冷门越值钱」的排序，机制倾斜也是「越冷门越优先」，
两者是同一流行度维度上的单调函数。

所以「让它产生独立战绩」只剩一条正路：用**真正能区分**的对照 —— 即
「按冷门偏好排序」vs「同池随机」（`ev/trials.py` 已经在跑的那套）。这也解释了
为什么不必给「机制倾斜 γ」单造对照：它本身就无法与 EV 排序分离。

### 为什么移除 pending 影子批次（`data/mechanism_trial.py`）

两条独立理由，任一条都足以否决：

1. **杠杆是空操作** ⇒ 对照两组逐注相同，入账等于记两排一样的号码再挂「在做对照实验」的横幅；
2. **会冲垮台账**：实验票若走 `feedback_history`，按「一注一行」计，滑轨 176 注/期 ⇒
   一届实验（约 2 期）就把战绩榜的 500 期窗口里全部生产样本顶掉。实验应走独立台账
   （`training/trials/`），这正是 `ev/trials.py` 的做法。
