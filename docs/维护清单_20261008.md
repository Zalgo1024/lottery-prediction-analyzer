### 4. 回归 baseline 恒失败 —— 已根治（`02f4aac`）

**根因**：baseline `_reg_ref.json` 存了两类依赖「采集当天 CSV 快照」的量——
`Xs_shape` 的行数（= 记录数 − 窗口）和 `preds`（三种单策略在当时最新数据上的输出）。
CSV 每期追加，行数一涨就必然失败：

```
双色球: Xs.shape [3461, 103] != ref [3440, 103]
大乐透: Xs.shape [2882, 99]  != ref [2859, 99]
```

**这不是代码回归，是数据在前进。** 而每次失败都去 `--update-ref` 刷新基准，
等于把「当前行为」固化成新基准，反而会掩盖真正的回归——这才是要防的事。

**修法：数据窗口钉死。** 新增 `scripts/regression_pin.py`，
baseline 记 `_meta.pinned_issue`（各彩种采集时的最新期号），
校验与采集都把输入截断到该期号：

- `records` 按 `期号 <= pin` 过滤。**期号必须按数值比**：`26114` vs `3001`，
  字符串比会翻转。
- `predict` 的输入也要钉：`prediction/engine.py` 顶层是
  `from data.loader import load_lottery`，须 patch **它自己的属性**，
  patch `data.loader` 对已导入的名字无效。
- baseline 缺 `_meta` 时退出码 2 并提示，不再拿全量数据做必然误报的比对。

**顺带修掉两处过期断言**（都是恒失败，与数据无关）：

| 断言 | 错在哪 | 修法 |
|---|---|---|
| v1 vs `train._build_features[0]` | `build_features` 第 i 个样本的窗口是 `records[i+1:i+1+ws]`（08-31 时间方向修正后的语义），脚本却拿 `records[:ws]` 比 → 窗口错位，实测 `max\|diff\|=1.0` | 改用 `records[1:1+ws]`，diff = **0.0** |
| `bf_y` 列数 | 标签是「每个号码一个二分类」，列数 = 号码总数（红+蓝）`49/47`；原断言拿它跟特征维数 `fd1(103/99)` 比，恒 False。`regression_check.py` 里同义那段还是 `if ...: pass` 的死代码 | 改比号码总数，死代码改成真断言 |

**证据**：老 baseline 按 `Xs_shape` 行数反解出采集窗口——双色球 ≤ **26093**（08-13）、
大乐透 ≤ **26091**（08-12），`preds` **一个字没改**。钉死后校验通过，
说明 **8-14 至今这 21/23 期里代码行为无回归**，原失败纯属数据前进。
判别性测试：剥掉 `_meta` 后校验退出码 2 并拒绝比对（证明不是空转）。

## 六、环境的三个坑（下次别再踩）

1. **`git push` 走不通，`git fetch` 能通** —— 沙箱代理只放行 GET，push 的 CONNECT 隧道返 502。
   所以"fetch 成功"推不出 push 也行。推送走 REST API 兜底（`.api_push_1008.py`，
   仓库名从 origin 动态解析、逐 blob 校验 sha、重试退避）。推完需手动
   `git update-ref refs/remotes/origin/main <远端sha>`，因为 fetch 做不到。
2. **乐透型 CSV 日期是 `D/M/YYYY`** —— 已修正 README，见第 2 条。
3. **探活 127.0.0.1 会被代理返回假 502** —— 本机设了 `http_proxy`，
   看板明明没起却看到 502，要用 `ProxyHandler({})` 绕过才能拿到真实的 10061。
